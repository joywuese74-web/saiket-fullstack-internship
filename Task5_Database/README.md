# Task 5 – Database Integration (PostgreSQL)

The Users REST API from Task 4, now connected to a **PostgreSQL** database hosted on **Neon**. Every endpoint runs an **SQL query**, so users are stored in a real database instead of a JSON file. Built for the SaiKet Systems Full Stack Development internship.

## What changed from Task 4

| Task 4 | Task 5 |
|--------|--------|
| Users stored in `users.json` | Users stored in a PostgreSQL table |
| IDs calculated in JavaScript | IDs generated by the database (`SERIAL`) |
| Duplicate emails checked in JavaScript | Duplicate emails blocked by the database (`UNIQUE`) |
| Data read/written with `fs` | Data read/written with SQL queries (`pg` library) |

## Database design

```sql
CREATE TABLE users (
  id         SERIAL PRIMARY KEY,                              -- auto-numbered, never reused
  name       VARCHAR(100) NOT NULL,                           -- required
  email      VARCHAR(255) NOT NULL UNIQUE,                    -- required, no duplicates
  age        INTEGER NOT NULL CHECK (age BETWEEN 1 AND 120),  -- required, 1 to 120
  created_at TIMESTAMP DEFAULT NOW()                          -- set automatically
);
```

The full schema and sample data are in `schema.sql`.

## Endpoints and the SQL behind them

| Method | Endpoint | SQL used | Success |
|--------|----------|----------|---------|
| GET | `/api/users` | `SELECT ... FROM users ORDER BY id` | 200 OK |
| GET | `/api/users/:id` | `SELECT ... FROM users WHERE id = $1` | 200 OK |
| POST | `/api/users` | `INSERT INTO users ... RETURNING ...` | 201 Created |
| PUT | `/api/users/:id` | `UPDATE users SET ... WHERE id = $4 RETURNING ...` | 200 OK |
| DELETE | `/api/users/:id` | `DELETE FROM users WHERE id = $1 RETURNING ...` | 200 OK |

### Example request (POST)
```json
{
  "name": "Wuese Joy",
  "email": "wuese@example.com",
  "age": 25
}
```

### Example response (201 Created)
```json
{
  "id": 4,
  "name": "Wuese Joy",
  "email": "wuese@example.com",
  "age": 25,
  "created_at": "2026-11-24T09:00:00.000Z"
}
```

## Features
- **Full CRUD** with SQL queries
- **Parameterized queries** (`$1`, `$2`, ...) to protect against SQL injection
- **Validation in two layers:**
  - in the API: name (at least 2 characters), valid email format, age (whole number 1–120)
  - in the database: `NOT NULL`, `UNIQUE` email, `CHECK` on age
- **Emails saved in lowercase**, so `Ada@Example.com` and `ada@example.com` count as the same
- **Partial updates** – `PUT` changes only the fields you send
- **Error handling** – database errors return clear messages instead of crashing the server

## Status codes

| Code | Meaning | When |
|------|---------|------|
| 200 | OK | Successful GET, PUT or DELETE |
| 201 | Created | A user was created |
| 400 | Bad Request | Invalid data, invalid id, duplicate email, or nothing sent to update |
| 404 | Not Found | No user with that ID, or an unknown route |
| 500 | Server Error | Unexpected database problem |

## How to Run

1. **Create the database table.** In your PostgreSQL database (e.g. on [Neon](https://neon.tech)), run the SQL in `schema.sql`.

2. **Add your connection string.** Create a file called `.env` in this folder:
   ```
   DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
   ```
   `.env` is listed in `.gitignore`, so the password is never uploaded to GitHub.

3. **Install and test the connection:**
   ```bash
   npm install
   node --env-file=.env test-db.js
   ```

4. **Start the server:**
   ```bash
   npm run dev
   ```
   The API runs at **http://localhost:3000**.
